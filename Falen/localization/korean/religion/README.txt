Korean religion localization
===========================

Layout
------
Each fs_religion_<id>_l_korean.yml owns one religion from
common/religion/religion_types. The filename omits the ID's _religion suffix.
Faith and rite names, descriptions, adherents, reformation names, and custom
religious terminology live together in that religion's file. Faiths and rites
that share an ID share their localization entries.

Shared files in common/:
- fs_tenets_l_korean.yml: tenet names/descriptions, selection requirements,
  parameter tooltips, syncretic opinion labels, and active vanilla overrides.
- fs_doctrines_l_korean.yml: doctrine groups, doctrine options, and descriptions.
- fs_families_l_korean.yml: custom family names and family name overrides.
- fs_holy_sites_l_korean.yml: holy site names and optional scripted effects.

Sources and inheritance
-----------------------
Use religion_types, faith_types, rite_types, tenet_types, doctrine_group_types,
doctrine_types, and holy_site_types as the source of truth. CK3 1.20 uses these
databases; common/religion/doctrines is the older format and is excluded from
the audit. Its files are left in place; this is not a gameplay migration.

Base-game Korean entries remain inherited unless this mod changes their text.
For example, the Buddhist, Confucian, Taoist, Muist, and Tengrist god names
currently referenced by the mod mostly use the base-game prefixes. Unreferenced
won_buddhism_*, mu_*, tengri_*, and naturalism_* god terms were removed instead
of redirecting the definitions to different gods. Catholic and historic rite
translations also remain inherited. Each YAML file identifies its source.

The imperial_* god terms stay in fs_religion_christianity_l_korean.yml, including
terms shared with Mechanism rites. Renaming a file does not change a key's scope.

Editing rules
-------------
- Save YAML as UTF-8 with BOM, start with l_korean:, and use _l_korean.yml names.
- Prefix every managed filename with fs_ to avoid replacing a base-game
  localization file. Keep localization keys as referenced by the game/scripts.
- Keep each key unique across the mod, including localization/replace.
- Religion, faith, and rite names normally use <id>, <id>_adj, <id>_adherent,
  <id>_adherent_plural, and <id>_desc. Explicit rite names override this stem.
- Tenets/doctrines use <id>_name and <id>_desc; groups use <id>_name.
- Include each dynamic name's possible desc key, not just its default name.
- Unreformed faiths also need <faith_id>_old and its adjective, adherent,
  adherent_plural, and description variants. These are generated by the engine
  during reformation and must not be removed merely because script omits them.
- Holy sites use holy_site_<id>_name. The optional holy_site_<id>_effects text
  must describe the current script, without inventing additional bonuses.
- Use $existing_key$ for intentionally shared text; avoid circular aliases.
- Match the actual definition ID even when it has a historic spelling, such as
  special_doctrine_adopt_monothesism. Fixing an ID requires a separate migration.

Some parameter markers have no implemented religious effect:
innovation_from_learning_traits, invasion_war, and old_world_war_bonus. Their
tooltip entries are deliberately empty and grouped under an explanatory comment.
The audit checks localization coverage; it does not prove mechanics work in-game.

Verification
------------
Requires Python 3.10+ and an installed CK3 game with Korean localization.
Run from the repository root, replacing the path with your installation:

python tools/validate_religion_localization.py --game-path "D:\SteamLibrary\steamapps\common\Crusader Kings III\game"

Add --inventory to print current religion -> faith -> rite mappings and lists of
custom tenets and doctrine groups/options. This index is derived from definitions.

The validator reports missing keys after base-game fallback, duplicate mod keys,
unused managed keys, malformed entries, missing BOM/header/filename suffix or
fs_ prefix, base-game filename collisions, and alias cycles. It follows explicit
localization blocks, dynamic descriptions,
custom tooltips, doctrine parameters/opinion overrides, reformation keys, selected
inherited tenets/doctrines, and script/alias references. It excludes comments and
the obsolete doctrines database. It is read-only and exits nonzero on errors.

After a passing audit, check religion/faith/rite panels, tenet/doctrine selection,
syncretic opinion tooltips, and faith reformation in CK3. The static audit cannot
verify engine loading, rendered text, or save-game compatibility.
